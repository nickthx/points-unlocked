# Phase 4 — UI Design Contract

> Visual and interaction contract for the guest core experience: balance entry → ranked results → shareable URL. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Scope note: Phase 4 builds real structure with existing tokens (per 04-RESEARCH.md Open Question 2 ruling — "don't ship gray boxes; don't chase pixel-perfection"). Destination imagery, animation (`motion`), and fine typography refinement are Phase 7 (PLAT-05). This contract governs what ships now.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, chip inner padding |
| sm | 8px | Label-to-input gap, inline metadata rows |
| md | 16px | Card inner padding (mobile), gaps between form fields |
| lg | 24px | Card inner padding (desktop), gap between result cards |
| xl | 32px | Gap between form block and results |
| 2xl | 48px | Section breaks (Bookable now / Almost there) |
| 3xl | 64px | Page-level top/bottom padding (desktop) |

Exceptions:
- **44px minimum touch target** for the 8 balance inputs and the Copy-link button — LinkedIn in-app WebView on a phone is the launch-critical session (STATE.md launch gate). Input height ≥ 44px; tap areas never smaller.

## Typography

Two weights only: **400 (regular)** and **600 (semibold)**. Two families: Inter (UI), Fraunces (display/headings).

| Role | Size | Family | Weight | Line Height | Usage |
|------|------|--------|--------|-------------|-------|
| Label | 14px | Inter | 600 | 1.4 | Program names on inputs, metadata rows ("via Chase UR → Hyatt 1:1"), "Verified Sep 1, 2026" stamp, chips |
| Body | 16px | Inter | 400 | 1.5 | Booking guidance (RANK-05), cash fare / cpp side-by-side figures, empty-state body, callouts |
| Heading | 28px | Fraunces | 600 | 1.2 | Section headings ("Bookable now", "Almost there"), redemption titles on cards |
| Display | 48px (`text-display` token) | Fraunces | 600 | 1.1, -0.02em tracking | **Per-card hero wow-delta figure** — the number that carries the drama (VAL-01) |

Declared exception: `text-display-xl` (72px / 1.05 / -0.025em, existing token) is permitted **only** for the single page-level hero headline/number, and clamps to `text-display` (48px) below the `md` breakpoint. Nowhere else.

Number rendering rules (binds executor):
- Hero delta = `wowDeltaCents.atMax ?? wowDeltaCents.atMin` — the exact conservative figure the ranking sorted on. Never render the optimistic end as the hero (04-RESEARCH.md Pitfall 4).
- Currency: `Intl.NumberFormat("en-US", { style: "currency", currency: "USD", maximumFractionDigits: 0 })` → "$4,500". Cpp: `(cppX100 / 100).toFixed(1) + "¢"` → "2.2¢".
- Verified stamp formatted by pure string helper from the ISO date — no `Date` object (Pitfall 5).

## Color

Existing `@theme` tokens in `globals.css` — do not introduce new color values this phase.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-cream` #faf7f2 | Page background, form area ground |
| Secondary (30%) | White `#ffffff` (`--card`) surfaces + `--color-ink` #262119 text | Result cards, input surfaces, all body/heading/display text (ink) |
| Accent (10%) | `--color-terracotta` #c05f33 | See reserved list below |
| Destructive | `--destructive` (existing oklch red) | Unused this phase — no destructive actions |

Accent (terracotta) reserved for exactly:
1. The wow-delta hero figures (per-card 48px display number and the page-level hero number)
2. The primary CTA button ("Copy my link")
3. The active transfer-bonus badge (VAL-05 surfacing, e.g. "+30% bonus until Oct 14")

Everything else — links, focus rings, section headings, path text, verified stamps, "points away" callouts — stays ink/muted. Focus rings use the existing `--ring` token. The delta IS the drama; diluting terracotta across the page kills the reveal.

Contrast note: terracotta #c05f33 on cream #faf7f2 ≈ 4.6:1 — passes WCAG AA for normal text and comfortably for the large display numbers; on white cards ≈ 4.9:1. Acceptable at all declared sizes.

| Page hero heading | "What are your points actually worth?" |
| Balance form helper | "Enter what you have. No account, nothing stored on our servers." |
| Empty state heading (no balances) | "Your points are worth more than you think" |
| Empty state body (no balances) | "Enter a balance above to see your best redemptions — like this one:" followed by one `featured` redemption teaser card (default per Assumption A5) |
| Sparse state (balances entered, both tiers empty) | "Nothing bookable with these balances yet. Add more programs above, or keep earning — Almost there shows what's within reach." |
| Section heading 1 | "Bookable now" |
| Section heading 2 | "Almost there" |
| Almost-there callout | "You're {formatted points} {program name} points away" (e.g. "You're 20,000 Chase Ultimate Rewards points away") — RANK-02 |
| Bank-point delta framing | "vs. ~{cashOut} cashing out" beneath the hero delta |
| Hotel-point delta framing | "Pure travel value — these points have no cash-out option" (Hyatt/Hilton/Marriott-funded results; Bilt uses bank framing per ratified 0.1¢ stand-in) — default per Assumption A2 |
| Transfer path line | "via {From} → {To} {ratio}" ; direct case: "Use your {Program} points directly" — RANK-04 |
| Bonus badge | "+{pct}% transfer bonus through {end date}" |
| Verified stamp | "Verified {Mon D, YYYY}" — VAL-04 |
| Error state | "Something went wrong showing your results. Refresh the page to try again." (neutral fallback; never render caught error details — T-01-07 precedent) |
| Destructive confirmation | None — no destructive actions in this phase. Clearing an input removes that balance silently (URL key drops; recompute is instant and reversible by retyping) |

Voice: confident, concrete, second person. Numbers do the persuading — no exclamation marks, no "amazing/incredible" adjectives near the figures (finance credibility is the pitch).

## Interaction & State Contract

Binding behaviors for planner/executor (all pre-decided upstream; listed here so the visual contract covers every state):

| State | Contract |
|-------|----------|
| Live recompute | Results re-rank on every balance edit via `useMemo` — no submit button, no loading spinners (engine is in-memory and instant). UI renders `bookableNow`/`almostThere` in engine array order; never re-sorts. |
| Input formatting | Thousands separators, whole points only, no negatives, `inputMode="numeric"` (mobile keypad). Placeholder "0". |
| Shared-link visit | SSR renders full results in initial HTML; visitor's own localStorage balances are NOT overwritten until they edit (Assumption A1 precedence — URL wins for display, editing claims ownership). |
| Reload persistence | Bare `/` visit hydrates from localStorage in an effect and pushes to URL with `history: replace` — no back-button spam, instantly shareable again. |
| Storage failure | Silently degrade to URL-only behavior (LinkedIn WebView guard) — no error UI for storage. |
| Balance tag | Each card shows which balance it uses (`chosenPath.fromProgramSlug` → program name) as a 14px label chip in ink/muted, not terracotta. |
| Responsive | Single column below `md`; inputs may sit in a 2-col grid ≥ `sm`. Cards full-width on mobile. Everything must work at 360px wide (WebView). |
