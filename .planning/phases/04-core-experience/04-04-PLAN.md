<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public URL → server render | Attacker-crafted share links hit the dynamic server component |
| localStorage → client state | Tampered storage crosses into URL + engine input on hydration |
| Client bundle | Everything imported into the island ships to every visitor |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-10 | Tampering | SSR of hostile searchParams | mitigate | loadBalanceParams (parseAsInteger) + paramsToBalances guard + engine sanitize — the same triple layer as client-side (T-04-01); array-valued/garbage params parse to null and drop |
| T-04-11 | Information disclosure | DB credentials in client bundle | mitigate | no @/db or drizzle import anywhere in the guest flow; grep-gated in Task 2 acceptance criteria; Phase 1 DB query deleted with the placeholder |
| T-04-12 | Information disclosure | error rendering | mitigate | engine call try/catch renders only the neutral UI-SPEC error string; caught error never rendered or logged (T-01-07 precedent) |
| T-04-13 | Tampering | storage-hydrated balances pushed to URL | mitigate | readStoredBalances validates wholesale before any setParams; hostile storage yields null → no hydration (tested in plan 04-01) |
| T-04-14 | Denial of service | clipboard/storage APIs absent in WebView | mitigate | try/catch on clipboard write (silent no-op) and guarded storage accessor — flow degrades to URL-only, never crashes |
</threat_model>
